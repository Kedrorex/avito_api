# Avito Republisher — PHP

PHP-приложение для взаимодействия с Avito API: синхронизация объявлений, сбор статистики, анализ производительности, переопубликование слабых объявлений и генерация XML-фида для Avito AutoLoad.

Коммерческое использование платное: 80 000 ₽ бессрочно или 20 000 ₽ на 12 месяцев, одна покупка на одну организацию. Смотреть код, запускать и менять его без заработка и без бизнеса можно бесплатно. Полный текст — в [LICENSE](LICENSE). Для оплаты напишите правообладателю репозитория.

## Развёртывание

Нужен PHP 8.1 или новее и расширения `pdo_sqlite`, `curl`, `mbstring`, `json`, `zip`. Из корня проекта:

```powershell
composer install
```

Создайте `.env` рядом с `index.php`. В Git его не кладите.

```dotenv
AVITO_CLIENT_ID=
AVITO_CLIENT_SECRET=
AVITO_USER_ID=

YANDEX_DISK_CLIENT_ID=
YANDEX_DISK_CLIENT_SECRET=
YANDEX_DISK_PUBLIC_URL=https://disk.yandex.ru/d/КОД
YANDEX_DISK_TOKEN=
YANDEX_DISK_PATH=
YANDEX_DISK_REFRESH_TOKEN=

# Локальное время ежедневного цикла, формат ЧЧ:ММ
RUN_AT=09:00
```

Первый запуск, по порядку:

1. Заполните ключи Авито в `.env`.
2. `php index.php sync` — активные объявления в `data/avito.db`.
3. `php index.php import-feed` — описание и фото из последней выгрузки Автозагрузки.
4. Настройте Яндекс.Диск по разделу ниже: опубликуйте XML, впишите ссылку, выполните `disk-auth`.
5. `php index.php run-r` — дневной цикл, файл только в `fid/`.
6. `php index.php run` — тот же цикл и перезапись файла на Диске.

В проде оставьте запущенным один процесс:

```powershell
php index.php schedule
```

Он читает `RUN_AT`, ждёт этот час и выполняет тот же цикл, что `run`. Закрытое окно останавливает ожидание. Планировщик Windows не используется. Пока цикл идёт, второй процесс на ту же базу не стартует.

Проверки без кабинета Авито и без сети:

```powershell
php scripts/test_account_isolation.php
php scripts/test_autoload_id_service.php
php scripts/test_autoload_id_sync.php
php scripts/test_feed_unique_id.php
php scripts/test_run_schedule.php
php scripts/test_yandex_disk_upload.php
```

## Команды

Все команды: `php index.php <команда> [аргументы]` из корня проекта.

Команды без префикса `account` работают с одним кабинетом: корневой `.env`, база `data/avito.db`, фид `fid/`. Дополнительные кабинеты описаны ниже, в разделе «Несколько аккаунтов».

Фид — это файл `fid/avito_feed_YYYY-MM-DD.xml`. У кабинета из реестра тот же файл лежит в `fid/{code}/`. В кабинет Авито загружается весь файл. Объявления, которых в нём нет, Авито снимает. Старый `Id` и новый `-vN` в одном файле вместе не пишутся: нет старого `Id` — объявление снимается, новый `Id` без `AvitoId` публикуется заново. За день так заменяется не больше `max_daily_repub` (70).

### Что запускать

`php index.php run` — обычный день и отправка на Яндекс.Диск. Синхронизирует активные объявления кабинета, подтягивает описание и фото из последней выгрузки, собирает статистику, пополняет очередь и пишет XML только из этих активных объявлений. Затем перезаписывает опубликованный файл кабинета: публичная ссылка в автозагрузке Авито остаётся той же. Строка из прошлой выгрузки, которой нет среди активных, в базу и в фид не попадает. Неопубликованное новое поколение тоже уходит из каталога, пока кабинет не отдаст его номер. Замена Id в файл из этой команды не пишется. Если ссылка или токен Диска не заданы, локальный XML всё равно появляется, команда завершается с ошибкой и Диск не меняет.

`php index.php run-r` — тот же цикл, файл только в локальной папке `fid/`. Яндекс.Диск не трогает.

`php index.php run-test` — тот же цикл, но очередь не списывается и новое поколение в базу не записывается. На Диск не отправляется. Синхронизация и статистика базу всё равно обновляют. С числом, например `php index.php run-test 5`, в файле новый `Id` получают первые 5 объявлений каталога, без очереди.

`php index.php feed --keep-queue` — только проверить XML по текущей базе, без синхронизации с кабинетом. Очередь и счётчик дня не меняются.

`php index.php feed` — боевой фид без повторной синхронизации кабинета. До 70 объявлений из очереди уходят с новым `Id`.

`php index.php republish-feeds 10` — тот же боевой фид, но новых `Id` не больше указанного числа (1–70).

Эти файлы в Автозагрузку не загружать, если не хотите снять лишнее:

- `php index.php feed-keep` и `php index.php feed-keep 10` — в файле только первые N объявлений. Остальных Авито снимет.
- `php index.php feed-inactive` — отдельный файл `fid/avito_feed_inactive_YYYY-MM-DD.xml` из неактивных кабинета и текущих активных. `feed-inactive --only-inactive` берёт только неактивные. `feed-inactive 100` ограничивает число неактивных.

### Фид и каталог

| Команда | Что делает | База | Пример |
|---|---|---|---|
| `run` | Дневной цикл и перезапись файла на Яндекс.Диске | Синхронизация, статистика, очередь. Замена Id в файл не пишется | `php index.php run` |
| `run-r` | Тот же цикл, XML только в `fid/` | Как `run`, Диск не меняется | `php index.php run-r` |
| `feed` | Боевой XML: порция очереди с новым Id, остальной каталог как был. Файл также уходит на Диск | Списывает очередь и создаёт поколение | `php index.php feed` |
| `feed --keep-queue` | Тот же XML для проверки. На Диск не уходит | Очередь и поколения не пишет | `php index.php feed --keep-queue` |
| `feed-only` | Как `feed`, но сначала добирает пустые `unique_id` | Как `feed` | `php index.php feed-only` |
| `republish-feeds <count>` | Как `feed`, порция не больше count | Как `feed` | `php index.php republish-feeds 10` |
| `feed-info` | Имя, дата и число объявлений последнего XML | Не меняет | `php index.php feed-info` |
| `feed-keep [count]` | XML только из первых N, по умолчанию 10 | Не меняет очередь | `php index.php feed-keep 10` |
| `feed-inactive [count]` | Отдельный XML неактивных и активных. На Диск не уходит | Не меняет очередь | `php index.php feed-inactive --only-inactive` |
| `upload-feed` | Последний боевой `avito_feed_ГГГГ-ММ-ДД.xml` на Диск, без нового прогона | Не меняет | `php index.php upload-feed` |
| `disk-url` | Показать публичную ссылку кабинета | Не меняет фид | `php index.php disk-url` |
| `disk-url <ссылка>` | Записать новую ссылку в env кабинета | Не меняет фид | `php index.php disk-url https://disk.yandex.ru/d/...` |
| `disk-auth` | Ссылка, чтобы разрешить приложению доступ к Диску | Не меняет фид | `php index.php disk-auth` |
| `disk-auth <код>` | Обменять код подтверждения на токен и записать его в env | Не меняет фид | `php index.php disk-auth КОД` |

Каталог фида — строки со статусом `active` и `low_perf`. Очередь сама по себе из каталога не выкидывает.

`feed-keep`, `feed-inactive`, `run-test` и `run-r` опубликованный файл не перезаписывают. `feed-only` и `republish-feeds` после боевого XML отправляют его на Диск, если ссылка и токен заданы.

### Данные кабинета

| Команда | Что делает | Пример |
|---|---|---|
| `sync` | Активные объявления кабинета в базу. Снятые с новым поколением не воскрешает | `php index.php sync` |
| `import-feed` | Последняя выгрузка Автозагрузки в базу: фото, описание, производитель, OEM | `php index.php import-feed` |
| `import-feed путь` | То же из локального xlsx, csv или xml | `php index.php import-feed fid/autoload/file.xlsx` |
| `import-feed путь --dry-run` | Только показать, что в файле, без записи. Путь должен быть вторым аргументом | `php index.php import-feed file.xlsx --dry-run` |
| `import-feed --force` | Скачать выгрузку заново, даже если этот отчёт уже импортирован | `php index.php import-feed --force` |
| `migrate-unique-id` | Заполнить пустой `unique_id` из сохранённого JSON, если он там есть | `php index.php migrate-unique-id` |
| `sync-unique-ids` | Дописать пустые Id автозагрузки | `php index.php sync-unique-ids` |
| `sync-unique-ids --all` | Запросить Id для всех активных номеров | `php index.php sync-unique-ids --all` |
| `active` | Активные строки базы, JSON | `php index.php active` |
| `status-counts` | Сколько объявлений в каждом статусе | `php index.php status-counts` |
| `ad <id>` | Строка базы и её статистика. Id локальный или номер Авито | `php index.php ad 4993` |
| `item <номер>` | Карточка из API Авито | `php index.php item 8285858647` |

Заглушка «заголовок и местоположение» из старого XML не затирает уже сохранённое HTML-описание. Пустой список фото не стирает уже записанные ссылки.

### Статистика и очередь

| Команда | Что делает | Пример |
|---|---|---|
| `collect-stats [days]` | Дневная статистика в базу, 1–270 дней, по умолчанию 30 | `php index.php collect-stats 7` |
| `stats [с] [по]` | Статистика из API за даты `YYYY-MM-DD`, JSON | `php index.php stats 2026-09-01 2026-09-20` |
| `collect-candidates [days]` | Объявления с нулём просмотров за N дней в очередь. Без числа берётся `candidate_days` | `php index.php collect-candidates 7` |
| `show-candidates` | Кто сейчас в очереди | `php index.php show-candidates` |
| `analyze` | Кто попадает под правила из конфига | `php index.php analyze` |
| `analyze-report` | То же с разбивкой по правилам | `php index.php analyze-report` |

`run` и `run-r` сами собирают статистику за `stats_days` (по умолчанию 3) и ищут кандидатов за 4 дня.

### Снятие через API, не через фид

`republish` и `republish-all` снимают объявление запросом к API. Это не файл автозагрузки. Количество обязательно, само все кандидаты команда не снимает.

```powershell
php index.php republish 42
php index.php republish-all 20
```

`republish-all` спрашивает подтверждение `yes/no`. Число не больше `max_daily_repub`.

### Как устроен фид

Если в каталоге 100 объявлений и в очереди 10:

1. Эти 10 получают новый `Id` (`-v2` или следующий `-vN`), без старого `AvitoId`. Заголовок, абзацы описания и порядок фото слегка меняются.
2. Остальные 90 пишутся как были.

Кандидаты берутся из `republish_candidates_*`, сначала самые старые. После боевой записи порция уходит из очереди, старая строка становится `deactivated`, в каталоге появляется новое поколение. Счётчик дня — `app_meta` `feed_repub_YYYY-MM-DD`.

Правила анализа в `config/avito.php`, ключ `analysis_thresholds`. Объявление кандидат, если подошло хотя бы одно правило.

## Автозапуск

`php index.php run` сразу выполняет дневной цикл. `php index.php schedule` не возвращается в консоль: читает час из `.env`, ждёт его, выполняет тот же цикл и снова ждёт. Остановка процесса останавливает ожидание.

Время лежит в `.env`, ключ `RUN_AT`, формат `ЧЧ:ММ`. Это локальное время. Меняете его вы: сохраните файл, работающий `schedule` перечитает строку. `php index.php schedule status` только показывает текущее значение.

Если процесс впервые видит час, который сегодня уже прошёл, сегодняшний цикл пропускается и начнётся завтра. После сегодняшнего цикла новый `RUN_AT` тоже действует со следующего дня. Пока один цикл идёт, второй не стартует.

## HTTP-режим

Рабочий способ запуска — команды CLI выше. `index.php` регистрирует маршруты Slim, но контроллер собирается только в консоли: у него обязательные аргументы конструктора, а контейнера для HTTP нет. Встроенный сервер `php -S` эти маршруты сам не выполнит.

## Конфигурация

### config/avito.php

Основные параметры:

```php
'avito' => [
    // Rate limiting
    'rate_limit_delay' => 8.0,              // Задержка между запросами (сек)
    'stats_request_delay_seconds' => 8,     // Задержка для stats API
    'request_timeout' => 120,               // Таймаут HTTP-запросов (сек)
    
    // Лимиты
    'max_daily_repub' => 70,                // Макс. републикаций в день
    'stats_days' => 3,                      // Дней для сбора статистики в run()
    
    // Кандидаты
    'candidate_days' => 4,                  // Дней по умолчанию для collect-candidates
    
    // Retry
    'max_retries' => 3,                     // Макс. попыток при ошибке
    'retry_delay_base' => 65,               // Задержка между повторными попытками (сек)
],

'analysis_thresholds' => [
    // Правила анализа — настраиваются без изменения кода
],
```

### Динамические параметры (days)

| Параметр | Где настраивается | Приоритет |
|---|---|---|
| `collect-stats [days]` | CLI аргумент | CLI > config default (30) |
| `collect-candidates [days]` | CLI аргумент | **CLI > config['candidate_days']** |
| `analysis_thresholds[].days` | config/avito.php | Конфиг (безопасное изменение без кода) |
| `stats_days` | config/avito.php | Используется в `run()` |

## Яндекс.Диск

Авито сам забирает XML по публичной ссылке. `run` перезаписывает уже опубликованный файл, адрес в кабинете Авито менять не нужно. Адрес лежит в env кабинета, в коде его нет.

Корневой кабинет — файл `.env`. Кабинет из реестра — `config/accounts/{code}.env`. Чужой токен и чужая ссылка в другой кабинет не подставляются.

### Настройка

1. На Яндекс.Диске опубликуйте XML, который будет забирать автозагрузка. Скопируйте ссылку вида `https://disk.yandex.ru/d/...`. В кабинете Авито в автозагрузке укажите эту же ссылку.
2. Создайте приложение на [oauth.yandex.ru](https://oauth.yandex.ru/client/new). Платформа — веб-сервисы. Redirect URI: `https://oauth.yandex.ru/verification_code`. Доступ: чтение и запись всего Диска. Доступа только к папке приложения недостаточно.
3. В env кабинета впишите:

```dotenv
YANDEX_DISK_CLIENT_ID=идентификатор_приложения
YANDEX_DISK_CLIENT_SECRET=секрет_приложения
YANDEX_DISK_PUBLIC_URL=https://disk.yandex.ru/d/КОД
YANDEX_DISK_TOKEN=
YANDEX_DISK_PATH=
```

`YANDEX_DISK_PATH` оставьте пустым: путь к файлу находится по публичной ссылке. Заполняйте его только если файл лежит внутри общей папки и в списке публикаций его нет.

4. Получите токен владельца этого Диска:

```powershell
php index.php disk-auth
php index.php disk-auth КОД_СО_СТРАНИЦЫ
```

Первая команда печатает ссылку. Откройте её, войдите в Яндекс-аккаунт, где лежит файл, и разрешите доступ. Код со страницы передайте второй команде. Токен запишется в `YANDEX_DISK_TOKEN`.

5. Проверка: `php index.php disk-url` показывает текущую ссылку. `php index.php upload-feed` отправляет последний локальный боевой XML. `php index.php run` делает дневной цикл и сразу отправляет новый файл. `php index.php run-r` оставляет файл в `fid/`.

Сменить документ:

```powershell
php index.php disk-url https://disk.yandex.ru/d/НОВЫЙ_КОД
```

Если файлы разных кабинетов лежат на одном Яндекс-аккаунте, Client ID, секрет и токен можно скопировать в env каждого кабинета. Публичная ссылка у каждого своя. Если Диск другой, для него нужно своё приложение и свой `disk-auth`.

## Несколько аккаунтов

Каждый дополнительный кабинет замкнут: свои ключи, свой файл SQLite, свой каталог фида. Объявления и `Id` автозагрузки между кабинетами не смешиваются. Общая схема таблиц внутри файла та же, колонки `account_id` нет.

Текущий кабинет в реестр сам не переносится. Его по-прежнему запускают без `account`.

### Добавить кабинет

```powershell
php index.php account add shop-2
```

Код — строчные латинские буквы, цифры, `_` и `-`, до 41 символа. `add` и `list` заняты командами. Повторный код не создаёт второй контур.

Команда создаёт:

| Путь | Что это |
|---|---|
| `config/accounts/shop-2.env` | Ключи Авито и Яндекс.Диска. Сразу пустые, заполняются вручную. В Git не попадает |
| `data/accounts/shop-2/` | Каталог базы. Файла `avito.db` ещё нет |
| `fid/shop-2/` | Каталог XML. Файла фида ещё нет |
| `data/control.db` | Реестр: код, пути, включён ли кабинет. Секретов там нет |

Дальше в `config/accounts/shop-2.env` вписать ключи Авито и свой Яндекс.Диск. Пока ключи Авито пустые, рабочая команда остановится и попросит их заполнить.

```dotenv
AVITO_CLIENT_ID=
AVITO_CLIENT_SECRET=
AVITO_USER_ID=
YANDEX_DISK_CLIENT_ID=
YANDEX_DISK_CLIENT_SECRET=
YANDEX_DISK_PUBLIC_URL=https://disk.yandex.ru/d/КОД_ЭТОГО_КАБИНЕТА
YANDEX_DISK_TOKEN=
YANDEX_DISK_PATH=
```

Ссылку в автозагрузке этого кабинета Авито поставьте на тот же документ. Токен:

```powershell
php index.php account shop-2 disk-auth
php index.php account shop-2 disk-auth КОД_СО_СТРАНИЦЫ
php index.php account shop-2 disk-url
```

`disk-url` без аргумента показывает ссылку. С аргументом записывает новую только в env этого кабинета.

Первая команда кабинета открывает `data/accounts/shop-2/avito.db` и создаёт таблицы. Строки из `data/avito.db` туда не копируются. Описание и фото берутся из выгрузки этого кабинета в `fid/shop-2/autoload/`, не из `fid/autoload/` корневого.

```powershell
php index.php account list
php index.php account shop-2 run
php index.php account shop-2 run-r
php index.php account shop-2 feed
php index.php accounts run
```

`account shop-2 run` после локального XML перезаписывает Диск этого кабинета. `run-r` пишет только `fid/shop-2/`.

`account {code} {команда}` выполняет любую команду из таблиц выше внутри этого кабинета. `accounts {команда}` проходит все включённые кабинеты по очереди. Ошибка одного пишется в отчёт и не останавливает остальных. Параллельно кабинеты не запускаются.

В кабинете Авито у каждого аккаунта должен быть свой URL автозагрузки на свой файл. Общий XML или общий URL смешает кабинеты: автозагрузка снимет всё, чего в её файле нет.

## База данных

Корневой кабинет: `data/avito.db`. Кабинет из реестра: `data/accounts/{code}/avito.db`. Список кабинетов: `data/control.db`, без объявлений и без ключей API.

### Схема

- **`physical_ads`** — поколения объявлений
- **`stats`** — legacy таблица статистики (обратная совместимость)
- **`statistics_YYYY_MM`** — партиционированная статистика по месяцам
- **`republish_candidates_YYYY_MM`** — кандидаты на републикацию
- **`stats_meta` / `candidates_meta`** — метаданные партиций

### Безопасность

- `PRAGMA foreign_keys = ON` включён автоматически при инициализации репозитория
- Имена партиций валидируются через regex `^(statistics|republish_candidates)_\d{4}_\d{2}$` перед использованием в SQL
- Все пользовательские данные экранируются через prepared statements

### Резервное копирование

```powershell
Copy-Item data\avito.db data\avito.backup.db
Copy-Item data\accounts\shop-2\avito.db data\accounts\shop-2\avito.backup.db
```

Копировать файл, пока скрипт пишет в эту базу, не стоит. `control.db` объявлений не хранит: для восстановления каталога нужен `avito.db` нужного кабинета.

## Лимиты Avito API

| Endpoint | Лимит | Текущая настройка |
|---|---|---|
| `GET /core/v1/items` | ~25 req/min | 8 сек (~7.5 req/min) ✅ |
| `POST /stats/v1/...` | ~1 req/min на пакет | 8 сек между пакетами ✅ |
| Макс. дней на запрос stats | 270 | Разбивка по месяцам ✅ |
| Макс. items в пакете stats | 200 | 200 ✅ |

Сбор просит поля `views`, `contacts`, `favorites` и их уникальные пары, группировка по дням. Без списка полей Авито не присылает избранное: в базе оно записывалось как 0, хотя в кабинете добавления были. Кабинет сравнивать с суммой тех дней, которые уже собраны (`collect-stats`), а не с коротким окном `run` (`stats_days`, по умолчанию 3). Старые строки обновятся при следующем сборе за тот же период.

Тайминги консервативные и безопасные для Avito API.

## Известные ограничения

- SQLite пишет в один файл одним процессом. Кабинеты из реестра идут по очереди: следующий открывается после закрытия предыдущего. Два процесса на один и тот же `avito.db` запускать не нужно
- Запросы к API Авито идут с паузами в несколько секунд. Длинный `collect-stats` занимает минуты и держит запись в файл базы
