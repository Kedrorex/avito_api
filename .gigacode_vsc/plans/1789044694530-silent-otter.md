# Модуль Переопубликования — Таблица кандидатов

## Цель

Создать механизм сбора объявлений-кандидатов для будущей републикации:
- Объявления с **суммарно 0 просмотров за 4 дня** после публикации попадают в таблицу кандидатов
- Объявление помечается статусом `low_perf` в `physical_ads`
- Таблица кандидатов **разбита по месяцам** (аналогично `statistics_YYYY_MM`)
- В будущем: из этой таблицы объявления будут переопубликованы и удалены

---

## 1. Новая таблица БД — `republish_candidates_YYYY_MM`

### Схема (partitioned by month)

```sql
CREATE TABLE republish_candidates_YYYY_MM (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    physical_ad_id INTEGER NOT NULL,
    avito_id TEXT NOT NULL,
    logical_key TEXT NOT NULL,
    added_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(physical_ad_id)
);
```

### Метаданные

Уже есть таблица `stats_meta` — используем её для учёта секций кандидатов.
Дополнительно: создаём таблицу `candidates_meta` (аналог `stats_meta`):

```sql
CREATE TABLE IF NOT EXISTS candidates_meta (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    partition_name TEXT NOT NULL UNIQUE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    record_count INTEGER DEFAULT 0
);
```

### Индексы

```sql
CREATE INDEX IF NOT EXISTS idx_republish_candidates_physical_ad ON republish_candidates_YYYY_MM(physical_ad_id);
CREATE INDEX IF NOT EXISTS idx_republish_candidates_avito ON republish_candidates_YYYY_MM(avito_id);
CREATE INDEX IF NOT EXISTS idx_candidates_meta_partition ON candidates_meta(partition_name);
```

## 2. Статус `low_perf` в `physical_ads`

Добавить новый статус для объявлений, которые попали в очередь кандидатов:

- Статус: `'low_perf'` (low performance)
- При попадании в таблицу кандидатов: `UPDATE physical_ads SET status = 'low_perf'`
- При републикации (будущая реализация): статус меняется на `'active'` для нового поколения

## 3. Методы в `ItemRepository`

### 3.1 Инициализация таблиц кандидатов

```php
private function initCandidatesTables(): void
```

- Создаёт `candidates_meta` если не существует
- Вызывается из `init()` (в конце, после основных таблиц)

### 3.2 Обеспечение существования секции

```php
public function ensureCandidatePartitionExists(string $partitionName): void
```

- Аналог `ensurePartitionExists()` для статистики
- Создаёт `republish_candidates_YYYY_MM` если не существует
- Записывает запись в `candidates_meta`

### 3.3 Получить секцию по дате

```php
public function getCandidatePartitionName(string $date): string
```

- Аналог `getPartitionName()` — возвращает `republish_candidates_YYYY_MM`

### 3.4 Найти кандидатов

```php
public function findZeroViewCandidates(int $days = 4): array
```

Возвращает массив объявлений, которые:
1. Статус `active` в `physical_ads`
2. `published_at` не старше `days` дней
3. Суммарный `views = 0` за последние `days` дней (из секций статистики)

**SQL-логика:**
```sql
SELECT pa.* FROM physical_ads pa
WHERE pa.status = 'active'
  AND pa.published_at IS NOT NULL
  AND julianday('now') - julianday(pa.published_at) <= :days
  AND (
    -- суммарные views = 0 за период из всех секций
    SELECT COALESCE(SUM(s.views), 0)
    FROM (выборка из всех statistics_YYYY_MM где physical_ad_id = pa.id
           AND date >= :date_from AND date <= :date_to) s
  ) = 0
```

### 3.5 Добавить кандидата

```php
public function addCandidate(int $physicalAdId, string $avitoId, string $logicalKey): void
```

- Вставляет запись в `republish_candidates_YYYY_MM` (секция по текущему месяцу)
- ON CONFLICT IGNORE (защита от дублей)

### 3.6 Удалить кандидата

```php
public function removeCandidate(int $physicalAdId): void
```

- Удаляет запись из всех секций кандидатов

### 3.7 Получить всех кандидатов

```php
public function getCandidates(): array
```

- Возвращает всех кандидатов из всех секций

### 3.8 Подсчёт кандидатов за месяц

```php
public function getCandidateCountForMonth(int $year, int $month): int
```

## 4. Методы в `RepublisherService`

### 4.1 `collectCandidates(int $days = 4): array`

Основной метод модуля:

1. Вызывает `$this->repository->findZeroViewCandidates($days)`
2. Для каждого кандидата:
   - Вставляет в таблицу кандидатов (`addCandidate`)
   - Обновляет статус в `physical_ads` на `'low_perf'`
3. Возвращает статистику: `['found': N, 'added': N, 'skipped': N]`

### 4.2 `removeCandidate(int $physicalAdId): void`

Удаляет объявление из таблицы кандидатов (будет вызвана при републикации):

1. `removeCandidate($physicalAdId)` из репозитория
2. Статус `low_perf` → `active` (или `removed` — зависит от логики републикации)

## 9. Детали SQL-запросов

### 9.1 Поиск кандидатов (суммарно 0 views за N дней)

```sql
SELECT pa.id, pa.logical_key, pa.avito_id, pa.published_at, pa.master_data
FROM physical_ads pa
WHERE pa.status = 'active'
  AND pa.published_at IS NOT NULL
  AND julianday('now') - julianday(pa.published_at) <= :days
  AND (
    SELECT COALESCE(SUM(s.views), 0)
    FROM (
      SELECT views FROM statistics_2026_09 WHERE physical_ad_id = pa.id AND date >= :date_from AND date <= :date_to
      UNION ALL
      SELECT views FROM statistics_2026_08 WHERE physical_ad_id = pa.id AND date >= :date_from AND date <= :date_to
      -- ... все секции за период
    ) s
  ) = 0
```

Для динамической подстановки секций используем PHP-генерацию UNION ALL из `getPartitionNamesForPeriod()`.

### 9.2 Вставка кандидата

```sql
INSERT OR IGNORE INTO republish_candidates_YYYY_MM
  (physical_ad_id, avito_id, logical_key)
VALUES (:pad_id, :avito_id, :logical_key)
```

### 9.3 Удаление кандидата

```sql
DELETE FROM republish_candidates_YYYY_MM WHERE physical_ad_id = :id
```
