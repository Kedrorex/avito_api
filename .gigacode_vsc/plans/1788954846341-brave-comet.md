# План: Секционирование статистики по месяцам

## Цель
Заменить единую таблицу `stats` на ежемесячные секции `statistics_YYYY_MM` для предотвращения раздувания БД и упрощения обслуживания.

## Текущее состояние
- Одна таблица `stats` с ~данными за все время
- Метрики: views, uniqViews, contacts, uniqContacts, favorites, uniqFavorites
- Метрика price хранится в `physical_ads.master_data` (JSON)
- 8 файлов обращаются к `stats` напрямую

## Изменения

### 1. Новая схема таблиц

#### `statistics_YYYY_MM` (динамически создаваемые)
```sql
CREATE TABLE statistics_YYYY_MM (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    physical_ad_id INTEGER NOT NULL,
    date TEXT NOT NULL,
    views INTEGER DEFAULT 0,
    uniq_views INTEGER DEFAULT 0,
    contacts INTEGER DEFAULT 0,
    uniq_contacts INTEGER DEFAULT 0,
    favorites INTEGER DEFAULT 0,
    uniq_favorites INTEGER DEFAULT 0,
    phone_shows INTEGER DEFAULT 0,        -- contactsShowPhone
    chats INTEGER DEFAULT 0,              -- contactsMessenger
    price INTEGER DEFAULT 0,              -- текущая цена объявления
    UNIQUE(physical_ad_id, date)
);
CREATE INDEX IF NOT EXISTS idx_stats_partition ON statistics_YYYY_MM(physical_ad_id, date);
```

#### `stats_meta` (метаданные секций)
```sql
CREATE TABLE IF NOT EXISTS stats_meta (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    partition_name TEXT NOT NULL UNIQUE,  -- 'statistics_2026_09'
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    record_count INTEGER DEFAULT 0
);
```

### 4. AvitoAPIClient — изменения

#### 4.1. Параметр `metrics`

В `getStatsV2()` добавить параметр `metrics` для запроса новых полей:
```php
'metrics' => ['views', 'contacts', 'favorites', 'contactsShowPhone', 'contactsMessenger']
```

#### 4.2. Лимиты API — КРИТИЧНО

| Ограничение | Значение | Решение |
|---|---|---|
| Макс сущностей на запрос | 1000 | Пакеты по 1000 itemIds с `limit=1000` |
| Глубина данных | 270 дней | Разбивать период на чанки по месяцам |
| Частота запросов | **1 в минуту** | **Пауза 120 секунд** между запросами (запас) |
| Метрика может отсутствовать | Да | Обработка `null`/`unset` gracefully |

**Реализация:**

1. `getStatsV2()` принимает `$metrics` массив (по умолчанию все доступные)
2. `requestStatsWithRetry()` — пауза **120 сек** между запросами (вместо текущих 60)
3. Разбивка периода по месяцам в `collectAllActiveStats()`:
   - Если период > 30 дней — разбиваем на чанки по месяц
   - Каждый чанк — отдельный запрос API
4. Обработка отсутствующих метрик:
   - `($stat['contactsShowPhone'] ?? 0)` — fallback 0
   - `($stat['contactsMessenger'] ?? 0)` — fallback 0

### 5. collect_1000_stats.php — изменения

### 6. Миграция данных

Скрипт `migrate_stats.php`:
1. Прочитать все записи из `stats`
2. Сгруппировать по месяцу (из `date`)
3. Создать `statistics_YYYY_MM` для каждого месяца
4. Вставить данные в соответствующие секции
5. Считать `stats_meta`
6. После подтверждения — переименовать `stats` → `stats_old`

### Разбивка по месяцам

```php
// Разбиваем период на чанки по месяц
function splitPeriodIntoMonths(string $dateFrom, string $dateTo): array {
    $chunks = [];
    $current = new DateTime($dateFrom);
    $end = new DateTime($dateTo);
    
    while ($current <= $end) {
        $monthEnd = (clone $current)->modify('last day of this month 23:59:59');
        $chunkEnd = $monthEnd < $end ? $monthEnd : $end;
        $chunks[] = [$current->format('Y-m-d'), $chunkEnd->format('Y-m-d')];
        $current = $monthEnd->modify('+1 day');
    }
    return $chunks;
}
```
